# 0002 — 서비스 추가에서 원본 그림을 보존한다

- 날짜: 2026-10-07
- 상태: 완료 — 2026-10-07, [수정·실제 편집 결과](../results/2026-10-07-preserved-addition/README.md). 사용자 시각 합격과 정렬 품질은 별도다.
- 근거: [KB 기준선](../results/2026-10-07-kb-baseline/README.md), [백로그 B008](../backlog.md)

## 범위와 선택

전체 JSON 재생성 대신 선택한 페이지의 원본 XML에 새 서비스 셀만 삽입한다.
기존 페이지·ID·소속·좌표·스타일·표·메모·수동 선·임의 metadata를 유지한다.
실제 편집기는 최신 XML과 활성 페이지를 함께 export해서 읽는다. headless 호출은 `pageId`를 명시하며,
다중 페이지에서 대상이 모호하면 원본을 유지하고 실패한다.
등록된 아이콘·크기를 재사용하고 새 서비스는 기존 아이콘과 겹치지 않는 자리에 둔다.
요청한 그룹에 자리가 없으면 기존 그룹을 임의로 늘리거나 다른 내용을 옮기지 않는다.

이번 범위는 서비스 추가의 보존 계약이다. 기존 정렬의 그룹 재생성이나 사람 수준의 자동 배치까지 해결됐다고 부르지 않는다.
ELK 채택·전면 재작성·AWS 호출은 포함하지 않는다.

## 작업과 검증

1. Kiro: 컨트롤러의 서비스 추가를 수정하고 합성 회귀 검사를 만든다.
   검증: 기존 셀·metadata 보존, 페이지 간 ID 반복, 명시적 대상, 잘못된 입력·실패 롤백, 새 셀의 위치/소속.
2. 조율자: bridge에서 최신 XML·활성 페이지를 반환하고 origin/source를 확인한다.
   검증: stale cache를 사용하지 않음, 외부 메시지 거부, 응답 누락/동시 export에서 조용히 덮어쓰지 않음.
3. 조율자: KB 두 파일의 7페이지를 각각 선택해 추가하고 전체 문서와 실제 화면을 비교한다.
   검증: vertex +1/edge 변화 0, 모든 기존 페이지·셀 보존, 다른 페이지 불변, 실제 iframe에서도 추가 1개.
4. 전체 테스트·빌드와 새 결과를 기록한다. 이전 기준선은 덮어쓰지 않는다.

완료: 명령 성공과 보존이 함께 통과하며 KB의 기존 화면 구조가 유지된다.
남은 정렬·라벨·연결선 품질은 별도 작업과 비교 항목으로 이어간다.

## 실행 결과

실제 루트/레이어 ID와 여러 레이어를 유지하도록 보완했다. 실제 편집기는 load로 페이지를 초기화하는 대신 merge 응답을 기다린다.
export와 merge는 요청 ID로 응답을 구분하고 동시 요청은 명시적으로 실패한다.
프로토콜은 [draw.io 공식 문서](https://www.drawio.com/docs/reference/embed-mode/)와 실제 iframe 응답으로 확인했다.
KB 추출 추가 7건과 전체 파일의 실제 페이지 선택 추가 7건이 명령·보존 함께 통과했다. 대상 외 페이지와 기존 셀 하위 XML도 불변이다.
12개 파일·166개 테스트와 빌드 통과. 새 vertex 겹침 0건이며, 실제 선·라벨 겹침과 기존 정렬 18건의 손실은 해결되지 않았다.
다음은 B007의 실제 SVG 지표와 B009의 경계를 유지하는 정렬이다. 기존 기준선은 그대로 보존했다.
