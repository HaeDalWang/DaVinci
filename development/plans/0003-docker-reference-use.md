# 0003 — Docker 웹 실행과 레퍼런스 활용

- 날짜: 2026-10-07
- 상태: B010 완료, B011 대기
- 사용자 요청: 실제 Docker 웹사이트에서 자연어로 만들고, 기존 회사 그림을 레퍼런스로 활용하고 싶다.
- 현재 근거: B008은 기존 XML의 서비스 추가 보존을 검증했다. 자연어 기반 새 그림 생성·전체 편집 품질을 뜻하지 않는다.

1. Docker에서 빌드된 웹과 API를 한 주소로 실행한다. 현재 다른 앱이 3000을 사용하므로 로컬 웹은 8080, 개발 API 기본은 3001로 구분한다.
   검증: 컨테이너 실행·HTTP·실제 화면·API 연결. 다른 앱은 유지한다.
2. 사용자가 `.drawio` 레퍼런스를 직접 열고 결과를 새 파일로 내려받을 수 있게 한다. 원본 회사 파일을 이미지에 넣지 않는다.
   검증: 실제 KB 파일 열기, 페이지 유지, 다운로드 XML. XML·스크린샷은 무시되는 `private.local/`에만 저장한다.
3. 자연어 입력에는 현재 선택한 페이지를 전달한다. 여러 페이지를 합쳐 모델에 보내면 중복 ID와 다른 페이지의 맥락이 섞인다.
   검증: 선택 페이지의 합성 회귀 검사, 잘못된/모호한 대상 거부, 브라우저 연결 확인.
4. 레퍼런스 복사 후 변경과, 새 그림의 스타일 참고를 구분해 다음 제품 범위를 기록한다. 사용자의 선택을 기다리면서 Docker 작업은 진행한다.

Kiro 소유: Dockerfile·compose.yaml·.dockerignore·server/index.js의 실행/정적 파일/모델 설정 안내.
조율자 소유: 프론트 API 주소·Vite proxy·파일 열기/다운로드·페이지 컨텍스트·기록/실제 검증.
기본 모델을 임의로 고르거나 자격 증명을 이미지에 포함하지 않는다. 실제 AI 생성 검증은 모델과 인증을 연결한 뒤 별도로 한다.
이번 작업은 로컬 실행이며 회사 서버 배포·사내 로그인·템플릿 저장소·RAG·학습은 포함하지 않는다.
