# 0007 — 입력과 템플릿으로 새 아키텍처 만들기

2026-10-08. 상태: 첫 구현 진행. B011의 사용자 의도가 확정되어 이 계획으로 이어진다.

## 합의와 입력 경계

- 목표: 리소스 목록·자연어·엑셀의 내용을 바탕으로 KB 수준의 그림을 생성한다. 85~90%는 희망 품질이며 아직 달성하거나 측정한 수치가 아니다.
- 입력에 명시한 리소스·소속·연결은 사실로 반영한다. 템플릿은 스타일·크기·간격·그룹 표현을 참고한다.
- KB에는 사람이 왜 배치했는지 설명이 없다. 시각적 포함만으로 서브넷·보안 의도를 확정하지 않는다. 중요한 누락·충돌은 질문한다.
- 원본 좌표와 고객 라벨을 정답 입력에 복사하여 재생한 결과는 새 생성의 합격으로 인정하지 않는다.

## 첫 단계 범위

1. 기존 XML 요약→생성 경로를 KB 7페이지로 측정한다. 원본 유지, 결과는 익명 숫자·해시만 저장.
2. 공통 입력은 기존 groups/services/connections 구조를 활용한다. 고유 ID, 타입, 부모·자식, 연결 참조와 순환을 검사한다. 미명시와 명시적 빈 연결 목록은 구분한다. 필요한 정보가 없으면 질문만 반환하고 그림을 바꾸지 않는다.
3. 선택한 페이지의 템플릿에서 인식 가능한 서비스/그룹의 표현만 참고한다. 새 입력에 없는 리소스를 추가하지 않는다. 원래 좌표·고객 라벨·연결은 새 구조에 복사하지 않는다.
4. 자연어 채팅의 새 생성 요청은 구조화된 입력으로 연결한다. 기존 편집과 생성은 명시적으로 선택한다. 생성은 새 페이지에 추가하고 모든 기존 페이지를 유지한다. 실패 시 기존 스냅샷으로 복원한다.
5. 명시적 입력을 가진 공개용 예시로 내용·스타일·질문·페이지 보존을 검증한다. 같은 입력의 기본 생성과 템플릿 적용 결과를 비교한다.

엑셀 파일 업로드/열 매핑은 공통 경로 이후 단계이며 이번 구현에 임의 포맷을 넣지 않는다. RAG·학습·회사 서버 배포는 범위 밖이다.

## 합격과 중단 기준

- 명시적 서비스·그룹·연결의 누락/중복/잘못된 참조 0. 잘못된 입력은 읽을 수 있는 질문/오류로 반환하며 XML을 쓰지 않는다.
- 생성된 페이지가 기존 페이지를 바꾸지 않는다. 템플릿의 크기·스타일을 적용해도 아이콘이 겹치거나 부모 경계 밖에 나가지 않는다.
- 기존 서비스 추가 회귀, 전체 테스트·빌드 통과. 핵심 연결과 실패 복원은 독립 검사.
- KB 실제 그림의 내용 정확성, 질문 적절성, 배치 가독성을 각각 평가한다. 교차/관통·라벨 겹침 미측정은 점수에 넣지 않는다. 실제 화면 승인 없이 85~90% 달성을 선언하지 않는다.
- 현재 저장된 브라우저 설정이 localhost 접근을 차단한다. 우회하지 않으며 실제 화면 검증은 권한이 변경될 때 진행한다.

## 역할

Kiro는 생성 핵심·기존 builder/layout의 최소 보완·채팅 생성 선택·서버 응답 안전 처리와 회귀 테스트를 맡는다. 조율자는 기준선·논의·계획·실제 KB의 읽기 전용 측정·diff 리뷰·최종 검증을 맡는다. 같은 checkout에서 파일 소유 범위를 분리한다.
