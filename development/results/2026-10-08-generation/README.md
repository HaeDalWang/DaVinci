# B018 — 생성 입력·질문·템플릿 첫 경로

2026-10-08. 진행 중. [사용자 합의](../../discussions/2026-10-08-generation.md), [실행 계획](../../plans/0007-reference-generation.md).

## 기준선

기존 요약→기본 생성의 KB 7페이지 결과는 [표](baseline-table.md), [원시 JSON](baseline.json), [재현 도구·소스 해시 포함 재측정](baseline-reproducible.json)에 보존했다. 두 측정의 records가 동일함을 확인했다.
원본 도형 797개/선 281개에서 생성 도형 529개/선 228개로 줄어든다. 도형에는 리소스·그룹·메모·장식이 포함되므로 누락된 AWS 리소스 수나 정확도 점수로 해석하지 않는다.

## 첫 구현 범위

명시적인 groups/services/connections 입력, 누락/모순 질문, 표현만 참고하는 템플릿, 기존 그림을 유지하며 새 페이지를 생성하는 경로를 구현한다. 공개용 [입력](../../fixtures/generation/explicit.json)은 좌표·고객 라벨을 포함하지 않는다.
엑셀 업로드와 KB 원본 전체 재생성·실제 눈 판정은 다음 B019/B020이다. 85~90%는 희망 품질이며 미측정이다.

## 역할과 권한

기존 Orca Kiro 세션의 Sonnet 5.5·medium·idle을 화면에서 확인한 뒤 작업 파일을 전달했다. 실제 파일 읽기와 구현 조사 화면을 확인했다. 구조화 Task/Dispatch는 앞선 agent_unconfigured로 성립하지 않았으며 직접 터미널 감독이다.
Kiro가 src/server/tests를 소유하고 조율자가 development 기록·측정·최종 검증을 소유한다. 같은 파일을 동시 수정하지 않는다. 워크트리를 추가하거나 삭제하지 않았으며 세션을 유지한다.
AWS/Bedrock 실제 호출·배포·커밋·푸시는 이 작업에서 수행하지 않는다. 저장된 localhost 브라우저 차단을 다른 도구나 URL로 우회하지 않는다. 실제 화면 확인은 별도 필요하다.

## 구현·조율자 최종 확인

- [Kiro 보고서](worker-report.md)의 구현을 리뷰하고 부족한 대화 경계·질문 형식·제어문자·큰 연결 입력 처리·조용한 기본 스타일 대체를 Kiro에게 수정 요청했다. 조율자는 제품 파일을 덮어쓰지 않았다.
- 생성/편집은 작업 방식 선택으로 구분하며 대화 기록도 따로 유지한다. 질문·응답 잘림·혼합 명령·잘못된 참조는 생성 전에 중단한다. 서비스/그룹 300개·연결 1000개 이하의 지원 범위다.
- 선택 페이지의 인식 가능한 스타일·아이콘 크기만 참고하고, 템플릿 라벨·좌표·ID·연결은 새 구조에 복사하지 않는다. 템플릿의 기존 리소스 목록은 생성 모드에서 모델에 보내지 않는다.
- 조율자가 직접 실행한 [전체 테스트](coordinator-test-output.txt)는 **20파일 301개 통과**, [빌드](coordinator-build-output.txt)는 성공이다. 기존 toast의 동적/정적 import 경고는 남는다.
- [독립 검사](coordinator-final/proof.json): 동일한 공개 입력(서비스 5·그룹 8·연결 4)으로 기본 생성 및 KB 7페이지의 표현 참고 생성이 통과했다. 입력 ID·라벨·소속·연결·템플릿 스타일/크기·기존 전체 페이지 보존과 형제 도형 겹침 0·부모 경계 초과 0을 확인했다. 소스 해시와 입력 해시를 함께 보존했다.
- 이것은 KB 7개 아키텍처의 완전한 재생성이 아니다. KB는 스타일 참고로만 쓰고 새 그림은 공개 입력으로 만들었다. 이전 임시 검사(coordinator-initial)는 스타일·소속 검사를 강화하기 전 결과이며 최종 근거는 coordinator-final이다.
- 조율자가 Dockerfile에 새 서버 import인 generation-flow.js의 포함을 추가했다. `docker build -t davinci:generation-check .`가 성공했고, 네트워크 없는 별도 일회성 컨테이너에서 [서버 health](docker-runtime-output.txt)를 확인했다. [이미지의 코드 해시](docker-source-hashes.json)가 로컬 server/catalog/generation-flow와 같음을 확인했다. 실제 8080 서비스는 갱신하지 않았다.
- 모호한 입력의 후속 질문과 모드 전환은 jsdom UI 테스트, 서버 응답은 mock Bedrock 테스트다. 실제 모델의 구조화 품질·draw.io 새 페이지 반영·웹 화면은 미검증이며 85~90%는 측정하지 않았다.
- 익명 숫자/해시와 공개 입력만 Git 대상이다. 생성 XML은 private.local에 둔다. 루트 PLAN.md·고객 원본은 유지했다. 커밋·푸시·실제 모델 호출은 수행하지 않았다.

## 사용 순서 (Docker를 새 코드로 갱신한 뒤)

1. 기존에 사용하던 `python3 development/tools/start-docker-with-default-aws.py`로 기본 프로필 인증과 새 코드를 반영한다.
2. 스타일을 참고할 그림/페이지를 선택하고 채팅의 작업 방식을 **새 그림 생성**으로 바꾼다.
3. 만들 리소스·그룹 소속·연결을 설명한다. 질문이 나오면 답하고 이어간다. 기존 그림의 리소스를 생성 요구사항으로 자동 복사하지 않는다.
4. 생성된 새 페이지 탭을 열어 확인하고 다운로드한다. 질문/오류이면 새 페이지를 쓰지 않는다.

## 남은 작업

B018은 로컬 구현·검증을 마쳤지만 실제 UI·모델 확인 전이라 진행 상태를 유지한다. Docker 새 코드 반영과 실제 화면 확인 후 완료 여부를 판단한다.
B019는 엑셀 입력과 열 매핑, B020은 KB에서 관측/추정을 구분한 전체 입력과 사람이 보는 배치 평가다. 기존 그리드 배치·제한적인 템플릿 그룹 인식은 KB 품질을 보장하지 않는다. 비AWS 도형·메모·자유 선을 포함한 전체 KB 생성은 별도 입력 표현과 검증이 필요하다.

## 사용자 확인용 웹 반영 — 2026-10-08

사용자가 결과를 먼저 보면서 점진적으로 진행하고 싶다고 요청했다. 기존 default AWS 인증 전달 도구로 Docker를 재빌드·재생성했다. localhost:8080의 `/api/health`는 status=ok, modelConfigured=true이며 HTML이 최종 검증 빌드의 index-3r1uzCjF.js를 제공함을 확인했다. 자격 증명을 출력하거나 실제 모델 요청을 보내지는 않았다. 위의 “현재 웹 미갱신”은 이 반영 전 상태다. 브라우저 화면의 직접 검증은 기존 접근 차단으로 여전히 미수행이다.

사용자는 KB에서 참고할 페이지를 선택한 뒤 새 그림 생성 모드에서 공개 입력 예제를 설명하고, 생성된 새 페이지를 확인한다. 기본 생성 XML과 KB 스타일 참고 생성 XML은 coordinator-final/private.local에 보존했다. 다음 품질 수정은 사용자의 첫 화면 평가와 B020 비교 기준을 따른다.
