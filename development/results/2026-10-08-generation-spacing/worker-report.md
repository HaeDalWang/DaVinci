# 생성 여백·긴 라벨 경로 보고 (B023)

모델/effort: claude-sonnet-5.5 / medium. 구조화 Dispatch 없음(agent_unconfigured), 직접 실행. git·브라우저·AWS/모델·배포 동작 없음. 아이콘 수정과 tiered 라우팅은 유지했다.

## 구현 (신규 생성 `tiered`에만 적용, 레거시 기본 40/50/80 유지)
- `layout-engine.js`
  - `LEGACY_METRICS`(패딩 40, 헤더 50, 간격 80)를 기본값으로 두고 `resolveAbsolutePositions`/`computeGridSize`에 메트릭을 전달. tiered일 때만 컴팩트(패딩 24, 헤더 max(32, ceil(fontSize×1.5)+14), 간격 48)를 쓴다. 헤더는 sanitize된 `groupStyles`의 fontSize로 늘어난다(`compactMetrics`, 라우터와 공유).
  - `estimateTextWidth`/`estimateLabelWidth`: 보수적 글자 폭 추정(ASCII 8px, 한글·한자 14px at 12px, 아이콘 40px). 그룹 최소 너비 = 라벨 추정 폭 + 패딩 → 긴 라벨이 헤더 안에 들어간다. 실제 렌더링 측정이 아니다.
  - 서비스 라벨 높이(30)와 템플릿 아이콘 크기는 그대로.
- `edge-router.js`
  - 통로 후보를 안쪽 오른쪽·왼쪽 다음에 **서브넷 바깥(부모 AZ 여백 안, 8px 간격, 경계 4px 이내로 제한)** 오른쪽·왼쪽으로 확장. 라벨 띠 검사는 끄지 않고 그대로 적용.
  - 아이콘 장애물은 아이콘 아래 라벨 폭 추정까지 포함. 이미 확정한 경로와 엄격히 직교 교차하는 후보는 버린다(교차하느니 기존 라우팅으로 남김).
  - (steering) 라우터가 `groupStyles`를 받아 레이아웃과 같은 fontSize·헤더 높이로 그룹 라벨 띠를 추정한다. `json-to-xml-builder.js`가 전달한다.
- 일반 라우터/레이아웃 프레임워크는 만들지 않았다.

## 한계
