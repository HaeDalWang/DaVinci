# B023 생성 여백과 긴 그룹 라벨 경로

2026-10-08. 사용자가 B022 웹 생성 화면을 “많이 괜찮아졌다”고 평가하고 계속 개선 요청했다. 화면에서 아이콘·AZ별 위아래 서브넷·S3 오른쪽 배치를 확인할 수 있다. 원본 좌표를 입력으로 쓰지 않는다.

다음 범위: 새 생성의 중첩 헤더/패딩을 줄이되 아이콘·라벨·명시 소속/연결 보존. 실제 화면의 Public Subnet A / Private Subnet A 같은 긴 그룹 라벨과 한글 라벨에서 선이 자동 라우팅으로 fallback하는지 재현하고 필요한 여백 통로를 보완한다. 기존 편집/레거시 배치의 상수는 유지한다.

합격: 같은 입력에서 면적 감소 및 서비스/그룹/선 보존, 공개 입력·KB 7페이지 참고 검사, 긴 라벨·비대칭 AZ·50px 템플릿 회귀. 긴 글자 폭은 보수적인 추정이며 실제 브라우저 글자 측정을 대신하지 않는다. 전체 테스트·빌드·Docker 웹 반영 후 사용자 눈 판정은 별도다.

## 구현·조율자 검증

Kiro Sonnet 5.5·medium 세션을 직접 터미널로 감독했다. 기존 agent_unconfigured로 구조화 Task/Dispatch는 성립하지 않았다. 제품 파일은 Kiro, development 측정/기록과 Docker는 조율자 담당이다. 사용자 화면 평가는 B022의 실제 동작·아이콘 표시 근거이며 이번 B023 화면 검증으로 대신하지 않는다.

- 생성 전용 간격: 패딩 40→24, 기본 헤더 50→32, 그룹 간격 80→48. 레거시 기본값·아이콘 크기·서비스 라벨 여백은 유지한다. 큰 그룹 글꼴은 헤더와 그룹 최소 폭을 늘린다.
- 화면의 긴 그룹 라벨에서 기존 inside 경로 2개가 fallback하던 문제를 재현했다. 부모 AZ 안의 서브넷 바깥 여백을 추가 후보로 써서 라벨 띠를 끄지 않고 통로를 만든다. 이미 정한 연결과 직교 교차하는 후보도 배제한다.
- 조율자 리뷰로 레이아웃과 라우터가 같은 groupStyles 글꼴·헤더 추정치를 사용하도록 보완했다. 실제 글자 폭을 재는 것이 아니며 서비스 라벨 글꼴은 12px 가정이다.
- [짧은 이름 기준선 비교](comparison.json): Cloud 874×906 →638×640, 면적 약48.4% 감소. [사용자 화면 이름 비교](screen-comparison.json): 같은 구조에서 Public/Private Subnet A/C·EC2 A/C·RDS A/C·로그 S3를 쓴 경우 874×906 →750×640, 면적 약39.4% 감소. 두 입력에서 서비스5·그룹8·연결4와 ID·라벨·소속·연결을 보존했다.
- 화면 이름의 지정 경로는 2→4개. 최종 지정 경로의 아이콘 관통0·엄격 직교 교차0. 이전의 자동 경로와 전체 draw.io 렌더링 경로는 미측정이며 공유 S3 줄기/합류는 교차 수에서 제외한다.
- 조율자가 [22파일331개 테스트](tests.txt)와 [빌드](build.txt)를 직접 다시 실행해 통과했다. 작업자 회귀는 3AZ·비대칭 개수·private만 있는 AZ·영어/한글·50px템플릿·28px 그룹 글꼴을 포함한다.
- [기본 공개 입력 검사](after/proof.json)와 [화면 이름 입력 검사](screen-after/proof.json)는 각각 KB7페이지 표현 참고·아이콘·내용·기존 페이지 보존·형제 겹침0·경계 초과0 통과다. 최종 소스 해시를 보존한다. after-initial은 글꼴 추정 보완 전 중간 검사다.
- [수정 전 공개 draw.io](example-before.drawio)와 [수정 후 공개 draw.io](example-after.drawio)는 고객 정보 없는 실제 생성 XML이다. KB 스타일을 참고한 XML은 private.local로만 보관한다.
- [Docker 갱신](docker.txt)을 완료하고 [health/최신 asset](web-proof.json)이 새 빌드 index-CXmA-Zbw.js를 제공함을 확인했다. 웹 새로고침 후 새로 생성해야 이번 간격이 적용된다. 실제 모델 호출은 하지 않았다.

## 남은 제한

직접 브라우저 화면 검증은 기존 접근 차단으로 미수행이다. 라벨 폭은 글꼴별 실제 폭이 아닌 보수적 추정이며 긴 서비스 이름/줄바꿈은 별도 확인이 필요하다. 임의 연결과 한정된 통로를 벗어난 입력은 draw.io 자동 라우터 fallback이다. 서브넷 종류가 없는 AZ는 주어진 요소만 배치하며 빈 그룹을 만들지 않는다; 서로 다른 서브넷 구성이 같은 의미 행에 정렬된다고 보장하지 않는다. 전체 KB 생성 품질85~90%는 미측정이다. 작업자 세션은 유지하고 커밋·푸시·워크트리 삭제는 하지 않았다. 다음 B020에서 KB 전체 관측 입력과 사람 눈 평가를 이어간다.

## 사용자 수정 후 화면 확인

사용자가 B023 반영 후 생성 화면을 공유했다. AWS 아이콘·위아래 서브넷·AZ 정렬·S3 오른쪽 배치가 표시된다. EC2→RDS 선의 우회와 채팅의 “기존 스타일을 반영하지 못했다” 문구는 후속 확인이 필요하다. 이 화면만으로 템플릿 적용 실패를 확정하지 않는다. 실제 브라우저를 조율자가 조작한 검증과 구분한다.
