# DaVinci 전반 검토 — 2026-10-06

`PLAN.md`는 이번 검토에서 읽거나 수정하지 않았다. 그 외 기존 구현과 설계 문서는 레거시로 보았으며,
새 구현이 기존 기술 선택이나 UI 방향을 유지해야 한다고 가정하지 않았다. 저장소 코드는 수정하지 않았다.

## 판단

실행 가능한 AWS 다이어그램 프로토타입이다. 다만 원본 그림의 데이터 보존, AI 명령 실행,
구조 재구성과 좌표 정렬의 구분이 제대로 성립하지 않는다. 새 개발에서는 이 세 부분을 우선 다시 설계해야 한다.
전체 코드를 그대로 보존할 필요는 없다. 아이콘 자료, 예제 XML, 기존 테스트의 유효한 검증 항목은 재활용할 수 있다.

## 현재 구조

- Vanilla JavaScript + Vite 프론트엔드, 외부 draw.io iframe, Express + Bedrock 백엔드.
- 제품 JavaScript 20개 파일, 테스트 7개 파일, CSS 1개 파일(1,264줄).
- 생성/편집: 채팅 → 키워드 기반 ChannelRouter → `/api/chat` → AI 명령 → DiagramController → iframe.
- 정렬: XML 요약 → 고정 AWS 계층으로 재구성 → 격자 좌표 계산 → 전체 XML 교체.
- 저장: localStorage의 최신 그림 한 개. 앱의 AI 되돌리기는 메모리 스냅샷이며 정렬에는 연결되지 않는다.
- 프론트엔드 API 주소는 `http://localhost:3000/api/chat`에 고정돼 있다.

## 예제 XML이 드러낸 테스트 빈틈

`example1.drawio`에는 vertex 91개와 edge 29개가 있다. 요약 결과는 서비스 45개, 그룹 22개,
연결 2개다. 29개 edge 중 source/target이 모두 있는 것은 2개뿐이어서, 나머지 27개 선은 요약에 들어가지 않는다.
이 수치를 27개의 논리적 서비스 연결이 사라진다는 뜻으로 해석하지는 않는다. 좌표 끝점으로 그린 선을
현재 교환 포맷이 표현하지 못한다는 증거다. vertex 중 나머지 24개도 서비스·그룹으로 표현되지 않는다.

현재 왕복 테스트는 주로 등록된 타입의 JSON에서 생성한 XML을 검사하고 개수를 비교한다.
실제 사용자 XML의 메모·원본 아이콘·수동 geometry·선 경로·ID 보존은 보장하지 않는다.
브릿지, 컨트롤러, 라우터, 대화 관리, 스냅샷을 직접 검증하는 기존 테스트도 없다.
따라서 84개 통과는 기존 검사 범위의 통과이며 사용자 편집 흐름이 안전하다는 증거는 아니다.

## 재사용 판단

- **자료로 재사용**: AWS 아이콘/그룹 스타일과 라벨, 두 예제 XML, 유효한 테스트 불변식.
- **구현 방식 참고**: draw.io JSON 프로토콜, XML escaping/상대좌표 계산, 작은 스냅샷 자료구조.
- **다시 설계**: 그림의 기준 데이터와 안정적인 ID, 변경 명령 검증과 적용, 구조 재구성과 배치의 분리,
  저장·되돌리기·동시 작업, AI 입출력 계약.
- **유지 의무 없음**: 현 UI/CSS, 키워드 라우터, 고정 3-tier/2-AZ 규칙, 기존 프롬프트,
  README/DESIGN/.kiro의 과거 설계. 새 요구와 실제 검증에 맞춰 선택한다.
