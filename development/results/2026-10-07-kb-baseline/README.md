2026-10-07. 입력은 [KB manifest](../../fixtures/baseline/kb-inputs.json)의 두 파일·7페이지다.
제품 코드는 `8d844fe`에서 바꾸지 않았다. [측정값](baseline.json), [전체 표](table.md).

## 결론

원본을 실제 draw.io에 로드하고 XML로 내보내면 7페이지의 ID·이름·순서와 측정 대상 내용이 보존된다.
하지만 레거시 정렬·서비스 추가는 **페이지 추출 변환 21건과 파일 전체 변환 6건 모두 보존에 실패**한다.
서비스 추가 9건은 성공을 반환하고 표지 1개를 추가하지만, 원본 보존까지 요구하는 명령 계약은 실패한다.
KB를 필수 대상으로 삼는 현재 기준에서 이 결과는 채택할 수 없다.

| 파일 전체 입력 | 원본 vertex/edge | 계층·좌→우 정렬 | S3 추가 | 원래 페이지 구조 보존 |
|---|---:|---:|---:|---|
| RA | 469/187 | 204/121 | 282/139 | 세 변환 모두 0/4 |
| 통합홈페이지 | 328/94 | 174/87 | 249/89 | 세 변환 모두 0/3 |

변환 출력은 `mxfile`의 여러 페이지 대신 단일 `mxGraphModel`이다.
일부 내용이 한 모델에 남아도 원래 페이지 ID·경계는 사라진다. 원본 페이지에 대응시켜 점수를 만들지 않는다.

페이지를 따로 꺼낸 진단에서도 RA `Architecture`는 195/79 → 정렬 111/63, 추가 151/73이고,
통합홈페이지 `운영(Multi-AZ)`는 156/48 → 정렬 90/44, 추가 120/45이다.
원본 ID가 재발급되는 문제도 있으며 ID 누락 수를 같은 수의 객체 삭제라고 해석하지 않는다.

- [로컬 비교 화면](http://localhost:5184/development/tools/kb-comparison.html): 7페이지와 파일 전체 2사례,
  정렬 2종·서비스 추가를 같은 배율로 비교한다. 파일 전체 원본 SVG는 활성 첫 페이지만 보여 주며 개수는 전체 합계다.
- [렌더 증거](render-proof.json): 실제 iframe의 origin/source를 확인한 load 이벤트 뒤 SVG 36개를 내보냈다.
  baseline 출력 hash → 브라우저가 fetch한 hash → 로컬 SVG hash를 연결한다.
- [원본 XML 왕복 증거](roundtrip-proof.json): 두 원본 전체 파일을 실제 draw.io에 로드해 XML로 내보냈다.
  7페이지의 ID·이름·순서와 vertex/edge의 ID·value·style·parent·geometry·끝점·kind가 유지됐다.
  루트 속성·임의 metadata 전체를 검사했다는 뜻은 아니다.
- [비교 화면 검사](comparison-proof.json): 9사례×3변환의 이미지 로드와 공통 50% 배율을 확인했다.
  조율자는 운영 그림의 원본과 변환 화면을 확인했다. 사용자 시각 합격 판정은 미완료다.
- [테스트](tests.txt): 10파일/124개 통과. [빌드](build.txt): 통과, 기존 toast import 경고 유지.

- Kiro Sonnet 5.5/medium이 [측정기 구현](kiro-worker-report.md)과 [도구 리뷰](kiro-tools-review.md)를 맡았다.

조율자 화면 관찰: 통합홈페이지 운영은 웹·AI·관리별 VPC와 별도 계정/외부 연결을 구분하며,

레거시는 고정 구조의 그룹 12개로 다시 배치한다. 단순 2AZ 대칭으로 원본의 역할·경계를 대체하면 안 된다.
화면 판정과 자동 보존 판정은 구분하며, 내용이 줄어든 그림의 면적·교집합 감소는 개선 근거로 쓰지 않는다.

## 재실행과 자료 범위

저장소 루트에서 새 출력 디렉터리로 실행한다. 다른 cwd에서도 측정기는 실행할 수 있다.

```sh
node scripts/measure-kb-baseline.mjs development/results/<새-이름>
```

렌더링은 Vite를 `localhost:5184`에서 실행하고 Orca에
`/development/tools/drawio-probe.html`을 연 뒤 `orca tab list --json`의 현재 페이지 ID를 사용한다.

```sh
python3 development/tools/render-kb-baseline.py development/results/<새-이름> <browser-page-id>
```

측정기는 입력 hash·페이지 ID/이름/순서·페이지 내 ID 중복을 검사하고 기존 출력은 덮어쓰지 않는다.
렌더링도 XML hash 불일치 시 브라우저 접근 전에 중단하며 기존 SVG/왕복 폴더는 덮어쓰지 않는다.
현재 비교 HTML은 이 결과 디렉터리를 가리킨다. 이후 측정은 별도 결과로 두고 비교 대상 경로를 연결한다.

XML·SVG·전체 셀 측정값·스크린샷은 `private.local/`에만 있다.
기존 `.gitignore`의 `*.local`로 제외되므로 Git으로 다른 기기에 전달되지 않는다.
원본 파일 역시 현재 로컬 입력이며 공유용 익명화가 완료됐다고 취급하지 않는다.
공유 가능한 기록에는 개수·hash·불투명 ID와 오류 분류를 남기고 고객 주소·내부 라벨·경고 메시지는 옮기지 않았다.

한계: 교차·관통·라벨 지표는 B007에서 미측정이다. 실행 시간은 변환 1회이며 기존 v2의 5회 분포와 직접 비교하지 않는다.
원격 draw.io 버전은 export에서 제공되지 않아 `null`이다. 사용자 시각 판정과 저장 파일 재열기는 이번 검증에 포함하지 않는다.
원본 XML 왕복과 SVG 렌더는 실제 iframe 검사이고, 변환 명령은 실제 제품 함수+메모리 어댑터 검사다.
실제 제품 UI에서 명령을 클릭한 전체 경로·AI·AWS 호출을 검증한 것은 아니다.

다음 구현 범위 제안(B006): 페이지를 선택해 원본 XML에 필요한 셀만 추가하고,
다른 페이지·기존 셀·수동 선·표·메모·미등록 도형을 그대로 유지하는 편집 계약부터 구현한다.
완료 기준은 KB 7페이지의 서비스 추가에서 명령과 보존이 함께 통과하고 파일 전체 페이지 구조도 유지되는 것이다.
그다음 B007과 배치 실험을 평가한다. ELK·전면 재작성은 여전히 미결이다.
