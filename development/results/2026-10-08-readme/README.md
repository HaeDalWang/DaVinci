# B017 — 쉬운 README와 실제 기준선 화면

2026-10-08. 사용자 요청: README를 15살도 이해할 설명으로 정리하고, 검사 기준을 스크린샷으로 보여 준다.

## 변경과 근거

- Kiro(`claude-sonnet-5.5`, 실제 화면의 `medium`)가 루트 README만 작성했다. 조율자가 실행법·검증 수치·이미지·최종 diff를 확인하고 보완을 요청했다. 다른 파일은 조율자가 기록했다.
- 기존 그림 편집 목적, AWS 용어, Docker 실행·사용 순서, 기준선의 의미와 합격 조건을 쉽게 설명한다.
- 실제 기준선 때 남긴 [합성 입력 화면](../2026-10-06-baseline/multi-az-original.png)과 [레거시 비교 화면](../2026-10-06-baseline-v2/comparison-page.png)을 그대로 재사용한다. 추가 이미지 파일이나 생성 그림은 만들지 않는다.
- 조율자가 두 이미지 파일을 직접 열어 보았고 고객명·계정 정보가 없는 화면임을 확인했다. KB 원본·사용자 화면은 README에 복사하지 않는다.
- 캡션에 촬영일·입력/초기 실패 결과의 용도를 적는다. 초기 비교의 각 칸은 그림 일부이며 전체 수치는 [v2 측정표](../2026-10-06-baseline-v2/table.md)를 따른다. 최신 서비스 추가의 합격 화면으로 해석하지 않는다.
- 최신 225개 테스트·빌드·KB 28건은 [B016 기록](../2026-10-08-multiservice/README.md)과 저장된 출력·JSON에서 확인했다. 이 문서 작업에서 제품 테스트를 다시 실행했다는 뜻이 아니다.
- 28건은 XML/controller 보존 검사이고 EC2·Lambda의 실제 KB peer 경로·선 교차/라벨 겹침·새 그림 생성 품질은 미검증이라고 명시한다. Docker 반영 상태는 확인 날짜를 적는다.

## 검증과 제한

- 조율자가 README의 로컬 참조 8개와 결과 문서의 로컬 참조 4개, PNG 이미지 2개의 파일 형식·내용·존재 여부와 `git diff --check`를 확인했다. 문서만 변경하므로 코드 테스트는 반복하지 않았다.
- 새 localhost 캡처는 브라우저의 저장된 사용자 권한으로 거부됐다. 다른 URL·브라우저·도구로 우회하지 않았다. 사용자에게 차단 이유와 설정 변경 방법을 알리고 기존 캡처를 재사용한다.
- Orca의 기존 Kiro 터미널에서 작업 파일 읽기·실행 화면·완료 응답을 확인했다. 앞선 `agent_unconfigured` 상태의 직접 터미널 감독이며 Task/Dispatch 실행으로 보고하지 않는다. 후속 작업을 위해 세션을 유지한다.
- 제품 소스·PLAN.md·고객 원본·Docker·AWS 호출은 변경하지 않는다. 이 요청으로 새 커밋·푸시를 하지 않는다.
