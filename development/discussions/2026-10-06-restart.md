## 확인한 근거

[초기 결과](../results/2026-10-06-initial/README.md)에 실행 명령과 재현 검사를 보존했다.
기존 테스트·빌드는 통과하지만 서비스 추가에서 메모·수동 위치·기존 ID 손실을 재현했다.
서비스 2개 합성 입력에서 연결 방향 반전이 배치에 반영되지 않았고, 기존 그룹을 버리는 것도 확인했다.
따라서 배치 점수만으로 개선을 판단하면 내용이 삭제된 그림을 좋은 결과로 오판할 수 있다.

## 원안과 현재 판단

원안은 기준선 → ELK → 의도 스키마 → AWS 규칙 → 증분 편집 순서다.
기준선부터 시작하는 방향은 합의했다. ELK는 실험 후보이며, 교체 완료나 채택을 결정한 것은 아니다.
원안의 “AI 문제가 아니라 배치 엔진 문제”라는 단정만으로 범위를 제한하지 않는다.
이번 검토에서는 데이터 보존과 명령 실행의 별도 결함도 확인했다.

현재 결정: [0001 — 기준선과 기록부터](../decisions/0001-baseline-first.md).
실행 계획: [0001 — 기준선](../plans/0001-baseline.md).

## 2026-10-06 — 개발 착수 후 확인

[고정 입력과 지표](../fixtures/baseline/README.md), [v2 기준선](../results/2026-10-06-baseline-v2/README.md)을 만들었다. 제품 소스를 바꾸지 않고 로컬 자동 측정 19개와 실제 렌더링 12개를 확보했다.

- 사각형 교집합을 한 숫자로 읽으면 포함 관계와 같은 위치의 노드 중첩을 섞게 된다. Kiro 리뷰를 받아 방법 v2에서 부분/포함/동일을 분리하고 v1을 보존했다.
- 포함을 사용자 의도라고 자동으로 인정하지 않았다. test2에는 같은 위치에 쌓인 서비스 아이콘도 있다.
- 정렬/추가 결과 12개 모두 원본 셀 보존 실패다. 성공해야 할 추가→삭제는 실패해 롤백되므로 보존 통과와 명령 성공을 따로 기록했다.
- 원본 보존과 안정적인 ID를 먼저 구현하는 방향을 제안한다. ELK나 전면 재작성 채택을 합의한 것은 아니다.
- 사용자 정답 그림 3개와 시각 판정은 미확보다. 실제 렌더 경로·라벨 지표는 후속 B007로 추적한다.
