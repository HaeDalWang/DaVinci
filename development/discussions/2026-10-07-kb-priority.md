# KB자산운용을 필수 검증 대상으로 삼는다

- 날짜: 2026-10-07
- 상태: KB 두 파일을 필수 대상으로 비교 준비 완료. 사용자 시각 합격 판정은 미결.
- 연결: [백로그 B005/B006](../backlog.md), [기준선 계획](../plans/0001-baseline.md)

## 사용자 지시와 적용

사용자 지시 요약: 다른 예제보다 KB자산운용이 가장 중요하며, 이후 KB 아키텍처가 제대로 나오지 않으면 의미가 없다.
따라서 KB 결과가 실패하면 다른 그림의 평균 지표가 좋아져도 개선을 채택하지 않는다.
KB 파일이 두 개 있으므로 둘 다 필수 대상으로 삼는다. 비교 화면은 통합홈페이지 운영(Multi-AZ)부터 보여 주며 두 파일의 필수 우선순위는 같다.
나머지 네 파일은 추가 회귀 검증 사례로 유지한다. 예제 수를 임의로 3개에 맞추지 않는다.

## 실제 입력 확인

`drawio-sample/`에 `.drawio` 파일 6개가 있다. KB 두 파일은 비압축 다중 페이지 XML이다.
원본을 수정하거나 복사하지 않고 XML 구조를 읽고, 각 페이지의 `mxGraphModel`을 기존 `measureXml()`에 전달했다.
아래 수는 AWS 서비스 개수가 아니라 XML vertex/edge 수다. 그룹은 측정기의 구조상 그룹 정의다.
고객 식별 값·주소·내부 라벨은 이 기록에 옮기지 않는다.

- `KB자산운용 RA 시스템 아키텍쳐 v1.6.drawio` SHA-256: `9e57ca339512c8bc356e91eaf062762285b48d776ab27e1ade9c54a45f9b21aa`
- `KB자산운용 통합홈페이지 아키텍쳐(운영 포함) v1.0.drawio` SHA-256: `c3475cabbc609fee87d503c528e9f9104467485d835026f68e13c80188c65732`

합계 7페이지, vertex 797개, 선 281개다. 선 42개는 source/target 참조가 둘 다 있지 않다.
이 선을 빠뜨리는 모델은 KB 원본을 표현할 수 없다. 표·표 행·일반 도형·사용자 정의 stencil도 포함된다.
페이지별 측정에서는 vertex 797개의 사각형 좌표를 모두 읽었고 dangling 참조는 0이었다.
이는 렌더링·아키텍처 의미·배치 품질의 합격 판정이 아니다.

기존 측정기에 파일 전체를 전달하면 각각 모델 4개/3개 오류로 거부된다.
페이지별 구조 측정은 가능하지만, 현 실행기는 이 두 파일을 전체 입력으로 재실행하지 못한다.
2026-10-06의 4입력/19사례 결과는 그대로 보존한다. KB의 변환 결과는 아직 측정하지 않았다.

## 검증 계약과 다음 작업

1. **입력 계약:** 두 파일의 페이지 ID·이름·순서와 원본 hash를 고정하고 페이지별 기준선을 만든다.
   한 페이지만 골라 읽고 나머지를 소실시키는 동작은 실패다. 기록·공유용 자료에는 고객 식별 정보를 남기지 않는다.
2. **보존과 명령 계약:** 기존 ID, 그룹 소속, 라벨, 스타일, 표·메모·일반 도형과 모든 선을 보존한다.
   참조가 없는 선도 끝점·waypoint와 함께 보존한다. 서비스 추가는 기존 geometry를 유지하고,
   명시적 정렬은 위치·경로 변경을 허용하되 연결 관계와 내용을 보존한다.
   편집 대상 외 페이지는 보존하며, 명령 성공 여부와 롤백 보존을 별도로 판정한다.
3. **화면 판정:** 운영/개발 경계, VPC/AZ/서브넷 소속과 연결 흐름이 읽히는지 원본과 비교한다.
   선 교차·아이콘 관통·라벨 겹침은 B007 또는 명시적 눈 판정으로 확인한다.
   사용자에게 확인받지 않은 결과는 시각 합격으로 기록하지 않는다.

현재 완료한 것은 입력 구조 확인과 필수 검증 우선순위 기록이다.
다중 페이지 기준선 실행, 실제 화면 비교, 사용자 시각 판정은 B005에서 이어간다.
ELK 채택·제품 재작성 범위는 이 지시만으로 확정하지 않는다.

## 후속 실행

사용자의 “계속” 지시에 따라 [KB 기준선·비교 결과](../results/2026-10-07-kb-baseline/README.md)를 만들었다.
페이지 추출과 파일 전체를 나눠 36건을 측정했다. 원본 draw.io XML 왕복은 통과하지만 변환 27건은 모두 보존 실패다.
실제 SVG와 공통 배율 비교 화면을 준비했으며, 보존 편집을 먼저 구현할 구체적 완료 기준을 B006에 제안했다.
사용자 시각 합격 판정과 ELK·재작성 채택은 이 결과만으로 완료 처리하지 않는다.

사용자는 비교 결과가 “아직 사람 눈에 부족”하다며 계속 수정을 요청했다.
[서비스 추가 보존 수정](../results/2026-10-07-preserved-addition/README.md)으로 KB 두 전체 파일의 7페이지에서 추가·보존이 통과했다.
기존 셀·경계·위치·선이 유지되는 것을 확인했으나, 기존 정렬과 라벨·연결선 품질 및 사용자 시각 합격은 남아 있다.
